# NOTES

Working notes — off-scope findings and operational gotchas. One line per item.

- Seed quirk (pre-existing, out of scope): some `languages` values are stored with an untrimmed comma (e.g. `'English, Hindi,'` style) — display-only, harmless, do not "fix" in this task.
- E2E `search-discover.spec.ts`: the destructive test (report + block) consumes the seeded demo deck and the `reports` per-pair unique constraint is one-shot, so it needs a fresh `supabase db reset` before re-running; it skips (not fails) once demo state is exhausted. Deck/match and search tests are idempotent.
- `buildSearchParams` returns a bare query string (no leading `?`) so it can feed `setSearchParams` directly; `parseSearchParams` accepts either form.
- Bug found + fixed by the e2e deck/report tests: `Modal`'s overlay `onClick={onClose}` fired on any click bubbling up from dialog content (buttons, inputs), so the report/block steps in `CardActions` could never be reached — the whole modal closed on the first content click. Fixed at the root in `Modal.tsx` (`event.target === event.currentTarget` guard).
- Bug found + fixed by the search e2e: `search_profiles` resolved a city centre from `city_coordinates` and then *immediately clobbered it* with the viewer's stored location (`coalesce(search_lat, viewer.latitude)`), so `?city=Bengaluru` measured distances from the viewer (≈830 km → `distant` buckets, empty `radius=10` results). Fixed in `supabase/migrations/20260929000020_search_discover.sql` — the fallback now only applies when the city lookup found nothing. DB re-reset required after this edit (done).- API gotchas learned this turn: Toast payloads take `description` (not `message`); `Modal`'s visibility prop is `isOpen` (no `open`); `Button` has no `danger` variant — destructive buttons are raw `<button className="bg-red-600 …">` (see CardActions).
- e2e ordering: `profile-likes-matches.spec.ts` sorts before `search-discover.spec.ts` alphabetically, so it must stay read-only for like/match state (search-discover's deck test expects demo to have liked nobody + aarav→demo still one-sided). Pause toggle inside it is self-restoring.
- `supabase test db` MUST run on a fresh `db reset`: after demo↔aarav are matched by the e2e, `11_profile_likes_matches.sql` tests 9-10/15-16 (untouched-seed assertions) and `10_search_discover.sql`'s plan(33) deck-count file both fail. Suite order: reset → pgTAP → e2e.
- `06_server_fields.sql` pins the exact column-grant set; adding `profile_paused` to the member-editable UPDATE set required updating that pin (23→24 columns, count 46→47 rows: 23 with INSERT+UPDATE, profile_paused UPDATE-only). This is contract maintenance, not a weakened test.
- Local demo seed (`local-seed/`, git-ignored): the personas are invented and the portraits are Unsplash stock photos. Real people's photos/details from third-party listings were deliberately not extracted — a seed file must never carry a real person's likeness or contact data. Photos are uploaded through the public storage API as each persona (anon key only) so the storage RLS and `record_member_photo` checks run exactly as for a real member; the SQL half runs as local `postgres`, same as `supabase/seed.sql`.
- Admin dashboard (migration 28): all six RPCs are SECURITY DEFINER + `is_admin()` + no `anon` grant. Reading a member record or a conversation writes an `admin_audit_log` row; the member payload returns `has_phone_number` (boolean) and never the number, because `private_contacts` has no administrator exception. `admin_get_conversation`/`admin_search_messages` are the only functions that return message bodies.
- Fixed a pre-existing routing bug: `AdminPage.tsx` was a default export while `routes/index.tsx` uses `lazyPage(..., 'AdminPage')`, so `/admin` rendered "Something went wrong" for every admin. It is now a named export, matching every other page.
- Pre-existing, still failing on a fresh `db reset` (not touched by the dashboard work): `01_schema_privileges` test 4, `06_server_fields` tests 1-2 (column-grant pins vs the `incognito` column added in migration 27), `08_security_contract` test 27 (RPC error text changed from "row-level security" to "You cannot message this person"), `safety` test 7 (3-reports hiding). `tests/e2e/admin.spec.ts` also logs in as `admin@local.test`, which no seed creates; `demo@local.test` is the seeded admin.
